# Write README Workflow

## Overview
Create comprehensive, user-friendly README files for software projects.

## When to Use
- New project initialization
- Open source project documentation
- Repository setup
- Documentation updates

## Workflow Steps

### 1. Understand Project Context
- Review codebase structure
- Identify target audience
- Understand installation requirements
- Note key features and use cases

### 2. Structure README

Standard sections:
```markdown
# Project Title
Brief description

## Features
Key capabilities

## Installation
Step-by-step setup

## Usage
Basic examples and API overview

## Configuration
Environment variables and options

## Contributing
Guidelines for contributors

## License
License information
```

### 3. Write Each Section

**Title & Description:**
- Clear project name
- One-sentence description
- Brief overview paragraph

**Features:**
- Bullet point key capabilities
- Focus on user benefits
- Include unique selling points

**Installation:**
- Prerequisites (Node.js version, etc.)
- Step-by-step commands
- Common installation issues

**Usage:**
- Basic example (quick start)
- Code samples with output
- Common use cases
- API overview if applicable

**Configuration:**
- Environment variables
- Config file structure
- Default values

**Contributing:**
- How to submit issues
- Pull request process
- Code style guidelines

### 4. Add Visual Elements
- Badges (build status, version, license)
- Screenshots or GIFs for UI projects
- Architecture diagrams if helpful
- Code syntax highlighting

### 5. Review Checklist
- [ ] Clear project description
- [ ] Complete installation instructions
- [ ] Working code examples
- [ ] Configuration documented
- [ ] License specified
- [ ] Contributing guidelines
- [ ] Contact/support information

## Quality Standards
- Installation instructions must work for new users
- Code examples must be tested and accurate
- Links must be valid and current
- Markdown properly formatted

# Design System Architecture Workflow

## Purpose
Guide systematic system architecture design process from requirements through implementation planning.

## When to Use
- Designing new system architecture
- Planning major system changes
- Evaluating architecture options

## Workflow Steps

### 1. Requirements Analysis
- Gather functional requirements (what the system must do)
- Identify non-functional requirements (performance, scalability, security)
- Understand constraints (budget, timeline, team)
- Document stakeholder needs

### 2. Context Mapping
- Identify system boundaries
- Map external integrations
- Understand data flow
- Document dependencies

### 3. Pattern Selection
- Evaluate architectural patterns (monolith, microservices, event-driven, serverless)
- Consider trade-offs for each pattern
- Match patterns to requirements
- Document rationale

### 4. Component Design
- Define system components
- Specify component responsibilities
- Design interfaces and APIs
- Plan data models

### 5. Trade-off Analysis
- List pros and cons of approach
- Evaluate scalability implications
- Consider maintenance overhead
- Assess risk factors

### 6. Documentation
- Create architecture diagrams
- Write technical specifications
- Document key decisions (ADRs)
- Provide implementation guidance

## Deliverables
- System architecture diagram
- Component specifications
- API design documentation
- Architecture Decision Records
- Implementation roadmap

## Best Practices
- Start simple, add complexity only when needed
- Design for change and evolution
- Consider operational requirements early
- Document decisions and rationale
- Validate architecture with stakeholders
